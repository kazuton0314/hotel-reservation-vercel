## 6.1 顧客索引 (`CustomerIndexService.js`)

### 対象

- **本予約のみ**（`03_` + `07_` アーカイブ）
- リクエスト台帳の人は **顧客IDを付けない**
- 同行者フォーム回答者も顧客索引には載せない

### 顧客キー

```
normalize(代表者名) + "|" + email
  or normalize(代表者名) + "|" + phone  (10桁以上)
```

- 姓名のみ（連絡先なし）→ キー生成不可 → **索引に載らない**

### 顧客ID

- 形式: `CU-{初回チェックイン年}-{NNNN}`
- 初回宿泊登録時に採番

### リピーター

- `来館回数` = 紐づく予約ID数（キャンセル除く、CI+COあり）
- **リピーター** = 来館回数 **≥ 2**
- UI: 顧客検索・詳細にバッジ表示

### 同期タイミング

- STUDIO/手動予約取込後（incremental）
- アーカイブ後
- メニュー手動同期 / 全件再構築

### スタッフ照会（リクエストの人）

- リクエスト詳細 **「この人の履歴」** → 顧客検索画面（OR検索、索引読取のみ）
- リクエスト時点での自動リピーター判定は **しない**

## 6.2 一覧検索（本予約・リクエスト）

### UI

1行: `[キーワード] [チェックイン日📅] [×]`

### キーワード（部分一致・OR的に各フィールドを探索）

| 対象フィールド |
|----------------|
| 代表者名, ふりがな, 姓, 名, 姓ふりがな, 名ふりがな, グループ名 |
| メール, 電話 |
| 予約ID, リクエストID |

- ひらがな/カタカナ正規化（`たなか` ⇔ `タナカ`）
- ID/電話: 数字2桁以上で部分一致（例: `0012` → `STUDIO-MT-0012`）

### チェックイン日

日付ピッカー選択時、**完全一致**で絞り込み（キーワードとAND）

### 挙動

入力280msデバウンスで自動フィルタ（検索ボタンなし）

## 6.4 部屋割りルール

### 人数表示

- ボード上の人数・内訳は **予約台帳（03）を正** とする
- 予約の人数項目を更新すると、紐づく部屋割行の内訳も同期

### 共有部屋

同一部屋・同一日に複数予約ID → `occ-shared` 表示  
割当変更時 `needsConfirm` → スタッフ確認ダイアログ

### 未割当

`assignmentStatus = 未割当` の予約を未割当列に表示（CI〜CO期間）

### ダッシュボード「部屋未割当」

**確定** かつ **未割当** のみカウント

## 6.5 メール送信ルール

### リクエスト

- 承認済 / 却下 かつ メールあり かつ 未送付 → pending

### 本予約

| 種別 | pending条件（要約） |
|------|---------------------|
| 予約確定 | 確定、メールあり、未送付 |
| 11日前 | 確定、CIまで≤11日、未送付 |
| 3日前 | 確定、CIまで≤3日、**宿泊2名以上**かつ同行者未回答、未送付 |

ダッシュボード「メール未送付」= 確定予約でいずれか pending

## 6.6 同期間予約表示

`apiGetOverlappingStays(checkIn, checkOut, excludeId, anchorDate)`

- 指定期間と滞在が重なる予約（キャンセル除く）
- **anchorDate**（通常=その予約のチェックイン日）基準で分類:
  - **チェックイン** — その日がCI
  - **チェックアウト** — その日がCO
  - **滞在中** — その日がCIでもCOでもない宿泊中日
